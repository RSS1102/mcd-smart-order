# 示例三：预算＋偏好点餐编译器

## 对话 A：有解（预算 35 元 + 不吃辣）

**用户**：预算 35 块以内，来个汉堡、薯条和可乐，不要吃辣。

> 第 1 步 —— 提取约束（`extractConstraints`）
```json
{
  "budgetMax": 35,
  "avoid": ["辣"],
  "requiredSlots": ["main", "side", "drink"],
  "itemCount": { "min": 1, "max": 4 }
}
```

> 第 2 步 —— 编译为可执行查询条件（`compileQuery`）
```json
{
  "channel": { "storeCode": "1420762", "orderType": 1, "beType": 1 },
  "priceRange": { "min": 0, "max": 35 },
  "slots": ["main", "side", "drink"],
  "excludeCodes": ["9900016073", "521953", "..."],
  "budgetRule": "30-40元：汉堡+薯条/小食+饮料",
  "mcpCalls": [
    { "tool": "query-meals", "args": { "storeCode": "1420762", "orderType": 1, "beType": 1 } },
    { "tool": "list-nutrition-foods", "args": {} },
    { "tool": "query-store-coupons", "args": { "storeCode": "1420762", "orderType": 1, "beType": 1 } }
  ]
}
```
注意：`beCode` 未出现 —— 到店自取场景禁止传。

> 第 3 步 —— 真实求解（`compileOrder`，搜索 2107 个组合，剪枝 459 次）

**助手**：✅ 找到 3 个满足全部约束的组合：

**方案 1（得分 72）**
- 双层深海鳕鱼堡三件套 ×1 ¥35.0　485 kcal
- 合计 **¥35.0**（原价 ¥47.5，省 ¥12.5）
- 营养估算：485 kcal ｜ 蛋白 28g / 碳水 46g / 脂肪 21g ｜ 钠 917mg
- 理由：预算利用率 100%；较原价省 ¥12.5；套餐已含主食+小食+饮料，无需凑单

**方案 2（得分 72）**
- 牛气满满套餐 ×1 ¥35.0　495 kcal
- 合计 **¥35.0**（原价 ¥47.5，省 ¥12.5）
- 营养估算：495 kcal ｜ 蛋白 26g / 碳水 42g / 脂肪 24g ｜ 钠 764mg

**方案 3（得分 71.43）**
- 板烧鸡腿堡三件套 ×1 ¥34.5　391 kcal
- 合计 **¥34.5**（原价 ¥47.0，省 ¥12.5）
- 营养估算：391 kcal ｜ 蛋白 23g / 碳水 35g / 脂肪 17g ｜ 钠 1041mg

> 含「麦辣」的餐品已被忌口规则排除，因此未出现在结果中。

## 对话 B：无解 → 最接近替代方案（含过敏原保护）

**用户**：预算 10 元以内想吃汉堡薯条可乐，热量不超过 300 大卡，我牛奶过敏。

> 提取约束：`budgetMax=10`、`calorieMax=300`、`allergens=["牛奶"]`、`requiredSlots=[main,side,drink]`

**助手**：

> ❌ 没有满足全部约束的组合。
>
> **未满足的约束**
> - 总价 ¥13.9 超出预算 ¥10
>
> 🔁 **最接近的替代方案**
> - 放宽了：热量上限 +10% → 预算上限 +10% → 件数上限 +1 → 热量上限 +25%（累计）→ 预算上限 +25%（累计）
> - 原因：总价 ¥72.5 超出预算 ¥10；热量 707 kcal 超出上限 300 kcal
> - **仍然严格保留：过敏原「牛奶」**
>
> - 精选超值随心配 ×1 ¥13.9
> - 合计 **¥13.9**
> - 理由：套餐已含主食+小食+饮料，无需凑单
>
> ⚠️ 即使放宽预算与热量，**牛奶过敏这条约束一步都没有放松**。如果你希望更贴近 300 kcal，
> 建议改为单点一份小食（如小薯条 210 kcal），或告诉我可以接受的最低预算。

## 对话 C：过敏原硬过滤

**用户**：我牛奶过敏，35 元以内配个汉堡和饮料。

> `ALLERGEN_RULES['牛奶'] = ['奶','芝士','奶酪','牛乳','奶油','拿铁','奶铁','冰淇淋','麦旋风','新地','奶昔']`
> 命中的餐品全部进入 `excludeCodes`，且**不参与松弛**。

验证（单元测试）：
```ts
const c = withC({ budgetMax: 60, allergens: ['牛奶'], requiredSlots: ['main','drink'], itemCount: {min:2,max:2} });
const r = compileOrder(menu, nutri, CHANNEL, c);
expect(r.feasible).toBe(true);
for (const it of r.combos[0]!.items) {
  expect(/奶|芝士|奶酪|奶油|拿铁|冰淇淋|麦旋风|新地/.test(it.name)).toBe(false);
}
```

## 对话 D：槽位无候选（门店售罄）

**用户**：我要一份早餐麦满分。

> 当前时间 15:44，该门店处于下午茶/夜市时段，菜单里没有早餐类餐品。

**助手**：抱歉，这家店当前时段没有早餐类餐品在售（可能已售罄或未到供应时段）。
要不要看看现在能点的？或者换一家 24 小时门店试试。

> 实现：`poolForSlot` 返回空 → `Violation{field:'slots'}`，
> 文案：「槽位『主食』在当前门店没有可用餐品（可能已售罄或被过敏原/忌口规则排除）」。
